# Power-ups (chum bucket and hatch) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the chum bucket (paid per throw; for 60 s the player's rare and legendary odds rise a lot) and the hatch (random 45 s event; the player's dry flies bite faster, and switching to a dry recipe swaps the fly on the line at once), each with a waving title on screen, plus insects during a hatch.

**Architecture:** Three timers on `GameState` (`chumMs`, `hatchMs`, `nextHatchMs`) driven by `tick`. Chum odds are applied in `rollCatch` through a new flag that the sim sets only for the player. Throwing chum lives in a new `progress/powerups.ts`. The hatch's wait change and fly swap live in `fishing/sim.ts`. Art (title letters, insects) and the letter wave and insect motion are pure functions. The scene and panel only read state and dispatch.

**Tech Stack:** TypeScript, Vitest, Phaser 4, HTML panel, Web Audio (synth).

**Spec:** `docs/superpowers/specs/2026-10-18-power-ups-design.md`

## Global Constraints

- Rules stay in `src/game/`. The panel and scene never compute odds, prices or timers themselves. The chum price shown is `chumPrice(state)`, which goes through `price()`.
- New `GameState` fields get defaults in `newGame()`. `SAVE_VERSION` stays 1. Power-ups are not in `Carry`.
- Functions that try to do something return `boolean`.
- Only `anglers[0]` gets chum odds, hatch waits or the swap. Helpers never do.
- Starting numbers, all in `data.ts` (Task 4 retunes `CHUM.cost` and only that):
  - `CHUM = { ms: 60_000, mult: 10, cost: { creek: 80, river: 500, bigRiver: 4_000, mountainLake: 30_000, greatLake: 100_000 } }`
  - `HATCH = { ms: 45_000, firstMs: 240_000, gapMinMs: 180_000, gapMaxMs: 360_000, waitMaxMs: 2_000 }`
- "Rare or better" means `TIERS.indexOf(tier) >= 2` (rare and legendary).
- Copy: titles `CHUM FRENZY!` and `HATCH! USE DRY FLIES`. The panel section is `Power-ups`. The chum row reads `Chum bucket` with the description `Rare and legendary fish bite more for 60 s`. The button shows the price (`$1.2K` style via `fmt`), `42 s left` while running, or `No rare fish within reach of your fly` when blocked. The hatch line reads `Hatch! Dry flies bite faster: 32 s`.
- Commits: one short imperative line, no trailers (user's rule).
- Every task ends with `npm test` and `npm run build` green.

## Review Focus

- A hatch wait shorter than the cast animation would bite before the fly lands. `HATCH.waitMaxMs` must stay above `TIMING.biteMinMs`, and the minimum must stay at `biteMinMs` (1.5 s, which is at least `CAST_MS + SINK_MS`). Test in Task 3.
- During a hatch with a dry recipe, a player who is broke and has an empty box still gets a dry fly (the free basic one), never `null`. Test in Task 3.
- A swap never loses a fly: box plus line holds the same flies, plus at most one newly tied one. Test in Task 3.
- A save with missing, `NaN` or negative timers loads with defaults (0, 0, `HATCH.firstMs`), and a save with a running bucket resumes it. Test in Task 1.
- A swap while waiting restarts the wait. The scene must show a clean recast, not a fish biting a fly mid-air. This is a manual check in Task 6 (no scene test harness exists).

### Task 3: Hatch rules and the dry-fly swap

**Files:**
- Modify: `src/game/fishing/flies.ts` (add `isDry`)
- Modify: `src/game/fishing/sim.ts` (`startWaiting`, `tick`, `castPlayer`, new `hatchSwap`)
- Test: `src/game/fishing/sim.test.ts`, `src/game/fishing/flies.test.ts`, `src/scene/fishing/choreo.test.ts`

**Interfaces:**
- Consumes: Task 1's `HATCH`, `hatchMs` and `nextHatchMs`.
- Produces:
  - `isDry(f: { patternId: string }): boolean`, true when the pattern's `cls === 'dry'`.
  - `startWaiting`: for the player with `hatchMs > 0` and `isDry(a.fly)`, the wait is `TIMING.biteMinMs + rand() * (HATCH.waitMaxMs - TIMING.biteMinMs)`. Otherwise it is unchanged.
  - `tick` handles the hatch after the anglers step:
    - while `hatchMs > 0`, it subtracts `dt`, and on reaching ≤ 0 sets `hatchMs = 0` and `nextHatchMs = HATCH.gapMinMs + rand() * (HATCH.gapMaxMs - HATCH.gapMinMs)`;
    - otherwise it subtracts `dt` from `nextHatchMs`, and on reaching ≤ 0 sets `hatchMs = HATCH.ms`.
  - `tick` then calls `hatchSwap(state, rand)` once.
  - `hatchSwap(state, rand): boolean` acts only when `hatchMs > 0`, `isDry(state.recipe)`, `p.fly` is non-null and not dry, and `p.phase` is `idle` or `waiting`. It then:
    1. moves `p.fly` to the front of `flyBox`;
    2. takes the first dry fly in the box, otherwise ties one from the recipe and takes it from the box's end, otherwise ties `basicRecipe()` and takes that;
    3. if `p.phase === 'waiting'`, calls `startWaiting` (re-picking the catch and restarting the wait).
  - `castPlayer` calls `hatchSwap` after picking up its fly and before `startWaiting`.
