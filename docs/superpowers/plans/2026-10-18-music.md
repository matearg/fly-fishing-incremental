# Background Music Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Six calm, slow chiptune tunes (title + one per place), synthesized in code, that never sound like a repeating loop, with their own volume row in Settings.

**Architecture:** A pure, Node-tested `src/audio/music.ts` holds the tunes as compact phrase strings, parses them into the existing `Note` type, and picks the next phrase with injected randomness. `SoundPlayer` gains a separate music gain node and a look-ahead scheduler that queues one phrase at a time, crossfading between tunes. Settings, menu and `TitleScene` get a second volume row by reusing the sound row's code.

**Tech Stack:** TypeScript, Web Audio, Phaser 4 (audio off), Vitest.

**Spec:** `docs/superpowers/specs/2026-10-18-music-design.md`

## Global Constraints

- Branch `feat/music` (already cut from `feat/sounds`).
- No audio files, no new dependencies. `src/audio/player.ts` stays the only Web Audio code; `src/game/` gets no audio code.
- Tunes: `title`, `creek`, `river`, `bigRiver`, `mountainLake`, `greatLake`. Each has **at least 6 phrases of about 4 bars**, tempo **60–80 BPM**.
- Parts: soft **square** melody, **triangle** bass, **gentle beat** (noise hat/brush + low quiet thump). No other parts. No drums beyond that beat.
- Picking: never the same phrase twice in a row; sometimes melody rests (bass + beat only); sometimes one melody note drops; the beat can change pattern between phrases and sometimes rests. Each tune starts from phrase 0 every time it comes in.
- Crossfade about **1.5 s** on any tune change. Music silent in a hidden tab, no burst of queued notes on return.
- Music setting: key **`flyfishing-music`**, same shape and rules as `flyfishing-sound` (levels 1–10, 10% floor, mute keeps level), default **level 5, unmuted**. Separate from the sound volume in both directions.
- Settings row right **below the sound row**, icon `NOTES`, text fallback `MUSIC 50%` / `MUSIC OFF`. Changing it plays the `move` blip.
- **Review stop:** after Task 3, the user listens to every tune on `/preview.html` and approves before Task 4 wires music into the game.

## Review Focus

- **Tab hidden for minutes, then shown:** music resumes within about a phrase, with no pile of overlapping notes and no notes scheduled in the past. Task 3 guards `nextAt` with `max(nextAt, now + small lead)`; checked live at the review stop.
- **Rapid tune switching** (Continue → Esc → Continue, or several travels in a row): old tunes fade and stop, at most one tune audible after 1.5 s. Task 3: `music()` with the same id is a no-op, a different id fades the old one; checked live.
- **Music volume 0 / muted while effects play, and the reverse:** muting one channel never changes the other. Task 3 routes music to its own gain node; Task 4 tests `musicMute` leaves `sound` untouched.
- **Corrupt `flyfishing-music` value** in storage: falls back to level 5, never throws. Task 4 test.
- **A tune with one phrase or a picker that always rolls "rest":** no infinite loop, and phrase 0 still opens with its melody. Task 1 tests the picker with `seqRand` at the edges (0 and 0.999…).

### Task 1: Phrase format, notes, and picker (`music.ts` core)

**Files:**
- Create: `src/audio/music.ts`
- Test: `src/audio/music.test.ts`

**Interfaces:**
- Consumes: `Note` from `src/audio/sounds.ts`; `seqRand`, `lcg` from `src/game/util/testutil.ts`.
- Produces:
  - `type TuneId = LocationId | 'title'`
  - `interface Phrase { melody: string; bass: string }`
  - `interface Tune { bpm: number; phrases: Phrase[]; beats: string[] }` — each beat pattern is one or more bars, repeated across a phrase.
  - `interface Pick { phrase: number; melody: boolean; beat: number | null; drop: number | null }` — `drop` is the index (into the melody's sounding notes) to leave out.
  - `tokens(src: string): string[]` — splits on whitespace, ignores `|` bar lines.
  - `pitch(name: string): number` — `A4` = 440 Hz, equal temperament, sharps as `C#4`; throws on anything else.
  - `phraseSteps(p: Phrase): number` — eighth-note count; throws if melody and bass differ.
  - `stepMs(t: Tune): number` — one eighth note in ms (`30000 / bpm`).
  - `nextPick(t: Tune, prev: Pick | null, rand: () => number): Pick`
  - `pickNotes(t: Tune, pick: Pick): Note[]` — times relative to the phrase start.
  - Gain/sound constants for the three parts live here (`MELODY_GAIN`, etc.), so tests can check them against the effects.

Token rules: melody/bass tokens are a pitch, `-` (hold the previous note one more step), or `.` (rest). Beat tokens are `h` (hat), `k` (thump), `.` (rest). A held note becomes one `Note` with the summed duration. Unknown tokens throw, like `paint` does for bad pixel rows.

Picker rules (exact chances are the implementer's, as named constants): `prev === null` → `{ phrase: 0, melody: true, … }`. Otherwise phrase is drawn from the others (never `prev.phrase`; a one-phrase tune just repeats 0). `melody` false with a small chance; `beat` null with a small chance, else a random pattern index; `drop` set with a small chance to a valid sounding-note index of the chosen phrase's melody.

### Task 3: Music channel in the player, preview section — REVIEW STOP

**Files:**
- Modify: `src/audio/player.ts`
- Modify: `src/preview.ts` (sounds section area, ~line 164)

**Interfaces:**
- Consumes: `TUNES`, `TuneId`, `Pick`, `nextPick`, `pickNotes`, `phraseSteps`, `stepMs` from Task 2.
- Produces on `SoundPlayer`:
  - `setMusicVolume(gain: number): void`
  - `music(id: TuneId | null): void` — safe to call every frame; same id is a no-op; remembered before `unlock()` and started by it, like `ambience`.

Approach:
- A second gain node, `musicMaster`, connected to `ctx.destination` (not through the effects `master`), created in `unlock()` with the stored music volume.
- Generalize the private `notes()` to take a destination node and a start time (`notes(notes, scale, pitch, dest = this.master, t0 = ctx.currentTime)`), so effects keep their current behavior and music reuses it.
- Each playing tune gets its own `fade` gain into `musicMaster`. On a change, reset `pick` to `null` (so the new tune opens with phrase 0), ramp the old fade to 0 over `MUSIC_FADE_S = 1.5` and disconnect it after; the new fade ramps 0 → 1 over the same time.
- Scheduler: one `setInterval` (~250 ms) created in `unlock()`. If a tune is playing, the context is `running`, and `nextAt - ctx.currentTime < 1` s: `pick = nextPick(tune, pick, Math.random)`, schedule `pickNotes` at `t0 = max(nextAt, ctx.currentTime + 0.05)`, then `nextAt = t0 + phraseMs / 1000`. A suspended context's clock stops, so a hidden tab queues nothing and resumes cleanly.
- Preview: a "Music (click to play)" section with one button per `TuneId` and a "stop music" button, using the same `button` helper pattern (`player.unlock()` then `player.music(id)`); set `player.setMusicVolume(0.5)`.
